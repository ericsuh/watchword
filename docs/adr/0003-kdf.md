# ADR 0003: Key derivation function

Status: accepted. Date: 2026-10-13.

## Context
The account password must be stretched before it is combined with the Secret Key. Argon2id is the
current best practice (OWASP minimum 19 MiB / 2 iterations / p=1), but Apple ships no Argon2
implementation; CommonCrypto ships PBKDF2 and CryptoKit ships HKDF. 1Password uses
PBKDF2-HMAC-SHA256 with 650,000 iterations and relies on the Secret Key for the bulk of the
resistance to offline attack. ADR 0001 forbids third-party crypto.

## Decision
- v1 uses PBKDF2-HMAC-SHA256 (CommonCrypto) with an iteration count calibrated at account creation
  to at least 650,000 and at least 300 ms on the creating device, stored in the account header.
- `KDFParameters` carries an algorithm tag and enforced minimums; a header below the minimum or
  with an unknown algorithm is rejected (SEC5). This prevents downgrade and leaves room for
  Argon2id.
- Argon2id becomes an option when either Apple ships it or an audited, pure-Swift (or Rust-backed,
  per ADR 0001) implementation is adopted through a new ADR. Migration re-wraps the keyset on next
  password unlock.

## Consequences
- The security of server-side ciphertext against password guessing rests on the 128-bit Secret
  Key, as it does in 1Password. PBKDF2 cost matters mainly for an attacker who already holds the
  Secret Key (device compromise), where it buys time rather than safety.
